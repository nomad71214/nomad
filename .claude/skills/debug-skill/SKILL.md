# 适用场景

- 新写的 skill 还没试过
- skill 试跑时卡住, 报错, 或结果不对
- skill 改过之后要确认没有引入新问题

# 第 1 步: 起子 agent 试跑

- 用 Task 工具起一个子 agent, 只给它两样东西
  - 读哪个 skill 文件
  - 要完成的具体任务
- 不给它额外的解释, 不给它已经知道的结论
  子 agent 只按 skill 文件执行, 才能看出 skill 缺什么
- 任务规模压小, 一次只覆盖 skill 的一段流程
  例如只跑「渲染页面」这一步, 不跑完整四步

# 第 2 步: 记录问题

按类归到下面五种, 一条一行

| 类型     | 表现                                   |
| -------- | -------------------------------------- |
| 缺步骤   | 卡在某处不知道下一步做什么             |
| 缺参数   | 命令缺必填项, 或不知道该填什么值       |
| 歧义     | 同一句话有两种读法, 子 agent 选了一种  |
| 路径错   | 相对路径层数不对, 或文件不在写的那个位置 |
| 多余要求 | 步骤做了但不影响结果, 或本来能一步做完 |

记录时写下子 agent 的原话与它执行的命令, 便于回溯

# 第 3 步: 改 skill

- 每次只改一类问题, 改完再看下一类
- 能删的不加, 能合并成一条的不拆成两条
- 命令写成可以直接复制的完整形式, 不写「运行 render 脚本」这类需要猜的说明
- 路径写相对仓库根的写法, 需要绝对路径的地方用 `%USERPROFILE%` 或 `$env:TEMP` 占位, 不写某一台机器上的具体路径
- 改完在文件里保留结果, 不写改动日志

# 第 4 步: 复查

- 起一个新的子 agent, 用第 1 步同样的任务重跑
- 对比两次的记录, 只关心原来的问题是否消失
- 出现新问题时回到第 3 步, 一次只改一类
- 连续两轮没有新问题时停下, 不再继续打磨

# 注意

- 不给子 agent 写「注意别出错」这类提醒, 问题应写进 skill
- 不让子 agent 直接改 skill, 只让它报告
- 试跑产生的临时文件放在 `$env:TEMP\nomad-debug\`, 不留在仓库里
