有一段内容想存进 NOMAD 时, 有三条路, 挑一条走就行

## 一个对话窗口里发给我

最省事, 也是平时该用的

把原文贴过来, 或者把图片, PDF 发过来, 说一句「整理成笔记, 放进 NOMAD」, 我会

1. 判断放哪个目录, 定标题
2. 按 `STYLES.md` 写正文, 补目录, 处理公式
3. 跑格式检查脚本, 修到 0 问题
4. 提交, 等你确认后再推送

适合整本教材, 课件, 长文档, 因为我可以直接读文件, 不用你复制粘贴

## 把别的 AI 的总结倒进收件箱

用网页版模型, 或者你还想先用别的工具过一遍

在 `Inbox/` 里新建一个 `.md`, 开头写两行指令

```markdown
<!-- folder: Coursera/[1]数学/(1)数学分析 -->
<!-- title: (13)反常积分 -->
```

下面接正文, 然后双击仓库根目录的 `新建笔记.cmd`
脚本会接管标题, 目录, 标点, 行宽, 提交与推送, 你只管倒内容

不写 `folder` 就落到 `Skill/速记`, 适合随手记

## 自己手写

打开 Obsidian, 在 `Coursera/` 下新建文件, 按 `STYLES.md` 写完
在 GitHub Desktop 里提交并推送

这条最自由, 也最容易写歪格式, 写完记得跑一次检查

```powershell
python .dsh\skills\markdown-format\scripts\check_style.py 文件路径
```

## 三条路都走同一根管道

不管走哪条, 后面的事是一样的

```text
文字或文件
   ↓  写成 Markdown, 放进 Coursera 或 Skill
本地 NOMAD 文件夹
   ↓  git 提交, 记录改了哪些文件
.git 里的本地历史
   ↓  git push, 把提交传到 GitHub
GitHub 上的 nomad 仓库
   ↓  仓库一有推送, GitHub Actions 自动跑 scripts/build_site.py
构建出的静态网页
   ↓  GitHub Pages 发布
https://nomad71214.github.io/nomad/
```

GitHub Desktop 只是给你看这条管道的窗口, 它显示的就是本地提交与远端之间的差额
本地多一笔提交, 它就提示你 Push, 推完差额归零, 窗口就干净了

## 三个常见疑问

改了内容但网页没变, 先看两件事: 提交了没有, 推上去了没有
页面更新有一两分钟的延迟, 因为 Actions 要排队构建

图片放哪里
放 `Annex/assets/年月/`, 正文用相对路径引用
例如 `![图1-1](../Annex/assets/2611/fig-1-1.png)`
没补的图保持空占位, 网站会显示成灰框

要不要手动改网页
不要, 网页是每次推送后由脚本重新生成的, 手改会被覆盖
想调外观改 `site/theme.css` 与 `site/app.js`
