# 什么时候用

用户给的是已经成型的内容, 不是整本教材

- 一段聊天记录, 一篇网页, 一份会议纪要, 一份 AI 生成的总结
- 用户明确说不要按章节结构写, 只要整理成一篇

整本教材或课件按章成篇时走 `textbook-to-notes`, 不要用这个

# 怎么做

1. 判断放哪
   - 学科内容进 `Coursera/[N]学科/(N)课程/`, 文件编号接着目录里已有的往后排
   - 工具与环境进 `Skill/`, 一个主题一篇, 不加编号
   - 论文笔记进 `Paper/`, 命名 `年份-简称.md`
   - 拿不准就问一句, 不要自己猜一个目录塞进去
2. 定标题
   - 学科笔记沿用目录的编号前缀, 例如 `(13)反常积分`
   - 其余用内容本身的标题, 不加编号
   - 标题里不要出现全角冒号
3. 写正文
   - 版式一律照 `STYLES.md`, 写之前先读一遍
   - 原文的章节顺序尽量保留, 不要为了凑结构重排
   - 原文里的外文术语、公式、代码原样保留, 公式统一换成 `$...$`
   - 原文没有的结论不要补, 拿不准的写在末尾「待确认」一节里
4. 自检
   - `python .dsh/skills/markdown-format/scripts/check_style.py <文件>`
   - 跑到 0 问题再往下走, 公式多的时候顺手在 Obsidian 里看一眼渲染
5. 落库并提交
   - `git add` 后提交, 提交信息 `[yy/M/d H:mm] 新增 <标题>`
   - 默认不 push, 等用户确认
   - 用户说「推上去」或「同步」再 `git push origin main`

# 也可以走收件箱

如果用户已经把内容存进了 `Inbox/`, 直接跑

```powershell
python scripts/inbox.py
```

脚本会读开头的 `folder` 与 `title` 指令, 自动整理标题层级、生成目录、跑格式检查、提交并推送
这种情况下不要自己再手写一遍, 免得重复入库

# 注意

- 一次只处理一篇, 用户给了三篇就写三个文件, 不要合并
- 长内容按原文章节拆 `##`, 不要为了行数硬拆
- 原文里的图片链接如果是外部地址, 保留原样, 不要下载转存
