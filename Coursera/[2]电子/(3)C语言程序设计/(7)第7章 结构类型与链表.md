## 7.1 结构类型的定义与访问

结构体把不同类型的数据打包成一个整体; 同类型结构变量可以整体赋值,
但不能用 `==` 整体比较, 成员的访问只看它是变量还是指针

(1) 结构体可以先 typedef 再省掉 `struct`, 也可以直接用匿名结构体定义变量
(2) 同类型结构变量能整体赋值, 效果是按成员浅拷贝
(3) 结构体不支持 `==` 比较, 要逐成员比或用 memcmp
(4) 变量用 `.` 访问成员, 指针用 `->`, `p->data` 即 `(*p).data`
(5) `.` 与 `->` 同级且左结合, `n2.next->data` 即 `(n2.next)->data`
(6) `typedef ... *DATE;` 里名字本身已是指针类型, 一律用 `->`
(7) 取地址 `&a` 是数组指针 `int (*)[N]`, 而 `a` 退化为元素指针

```c
typedef struct { int id; int score[3]; } Student;
Student stu[3];
int *p = stu[0].score;   /* 数组名退化为 int * */

struct Node { int data; struct Node *next; };
printf("%d", node.next->data);   /* 即 (node.next)->data */
```

[注意] `sum / C` 两个整数相除会截断, 要写 `(float)sum / C`;
`*p[j]` 等价 `*(p[j])`, 把整数值当地址用

例7-1: 关于结构变量的说法错误的是
A. 结构变量之间不能用 == 比较成员  B. 结构类型定义时一定要有类型名称
C. 同类型结构变量可以直接 `b = a` 赋值  D. 可用结构指针的 -> 访问成员

解: B. 匿名结构体合法, 如 `typedef struct { int id; } Student;` 就没有
tag

例7-2: 统计每位学生三门课的平均分, 保留两位小数, 找出 4 处错误
(`struct Student stu[N]`, `p = &stu[i].score`,
`sum += *p[j]`, `sum / C`)

解: 去掉 `struct`; 改 `p = stu[i].score`; 改 `sum += p[j]`;
改 `(float)sum / C`. typedef 后 Student 就是类型名,
数组名退化才是 `int *`, 整数除法要有一方是浮点

例7-3: `struct Node {int data; struct Node *next; } n1 = {10, NULL},`
`n2 = {20, &n1};` 则 `printf("%d", n2.next->data);` 输出
A. 10  B. 20  C. NULL  D. 编译出错

解: A. `n2.next` 是 `&n1`, 取 `n1.data` 得 10; 这种在定义时用地址串起结点
的写法叫静态造链表

例7-4: `typedef struct date { int year; ... } *DATE;` 且
STUDENT 的成员是
`DATE birthday;`, 对 `STUDENT pp` 输出出生年月正确的是
A. `pp.DATE->year`  B. `pp.birthday->year`
C. `pp.birthday.year`  D. `pp->DATE.year`

解: B. typedef 名后面带 `*` 时它本身就是指针, 访问要用 `->`;
pp 是结构变量本身, 用 `.`

例7-5: 下面叙述错误的是
A. 实型数组不能用数组名整体 scanf 与 printf
B. 字符数组可以用 %s 整体输入输出
C. 字符型数组可以存放字符串
D. 含数组的结构体变量可以用 = 整体赋值

解: 四条在标准 C 下都成立, 本题没有唯一答案.
结构体整体赋值会把成员数组一并按字节拷贝, 不能整体赋值的只有数组本身

## 7.2 链表与数组

数组随机访问快而插入删除慢, 链表插入删除快而随机访问慢;
单链表只能从头走, 找前驱是它最大的成本

(1) 链表结点用 malloc 动态申请, 空间分散, 不需要预先分配
(2) 已知位置时链表插入与删除只改指针, 是 O(1)
(3) 数组插入删除要搬移后续元素, 是 O(n)
(4) 数组能按 `a[i]` 直接算出地址, 链表必须从头逐个走
(5) 单链表只有后继指针, 因此常引入辅助表元简化首结点的边界
(6) 链表每个结点多存一个指针, 空间开销比数组大

```c
struct Node { int data; struct Node *next; };
/* 数组: 随机访问 O(1), 插入删除 O(n) */
/* 链表: 随机访问 O(n), 已知位置的插入删除 O(1) */
```

例7-6: 关于链表说法错误的是
A. 结点可以通过动态分配获得  B. 链表删除效率更高
C. 链表插入效率与数组相同  D. 单链表遍历要从首表元开始

解: C. 错在"相同": 链表改指针是 O(1), 数组还要搬元素, 整体是 O(n)

例7-7: 链表相较数组的重要优势是
A. 支持随机访问  B. 插入删除不需移动其他元素
C. 占用空间更少  D. 查找元素更高效

解: B. A 恰好说反了, C 与 D 都是数组占优

## 7.3 链表的插入与删除

链表的改动永远是"某个结点的 next 字段", 不是游标指针本身;
插入先接后, 再接前, 删除先保后路, 再改指针, 最后 free

(1) 结点成员必须写成 `struct node *next`, 写成 `struct node next`
无法确定大小
(2) `if (head->data = n)` 是赋值, 比较要写 `==`
(3) 删除后继时判断的是 `p->next->data`, 因为 p 停在前驱上
(4) malloc 写 `sizeof(struct Node)` 而不是
`sizeof(struct Node *)`
(5) 要停在尾结点, 循环条件写 `temp->next != NULL`
(6) 插入写 `temp->next = newNode`, 不能写 `temp = newNode`
(7) 函数末尾必须 `return head;`, 否则返回值不确定

```c
newp->next = pre->next;     /* 先接后 */
pre->next  = newp;          /* 再接前, 顺序不能反 */

node = node->next;          /* 先保住后继 */
free(middle);               /* 再释放 */
frontend->next = node;       /* 最后摘除中间一段 */
```

[注意] `malloc(sizeof(struct Node *))` 编译不报错, 但只申请了 8 字节,
写 `next` 时就越界, 数据量一大才崩

例7-8: 删除值为 n 的结点函数有 3 处错误
(`struct node next;`, `if (head->data = n)`,
`if (p->data == n)`)

解: 改 `struct node *next;`; 改 `==`; 改
`if (p->next->data == n)`.
第 13 行删的是后继, 判断的也应是后继的值

例7-9: 把数据插入链表末尾的函数有 3 处错误
(`sizeof(struct Node*)`, `while (temp != NULL)`,
`temp = newNode;`)

解: 改 `sizeof(struct Node)`;
改 `while (temp->next != NULL)`;
改 `temp->next = newNode`. 空链表还要提前 `return newNode;`,
否则空指针解引用

例7-10: 带辅助表元的升序链表删除 min 到 max 区间, 填 25.6 到 25.9
(`frontend = ___`, `while (node && ___)`, `___;`,
`___ = node;`)

解: `head`; `node->data <= min`; `free(middle)`;
`frontend->next`.
辅助表元保证一个都不删时也有合法前驱, 值是 min 的结点要保留, 所以用 `<=`

例7-11: 带辅助表元的升序插入, 填 4.2.1 到 4.2.5

解: `break`; `newp->next = pre->next`; `pre->next = newp`;
`head, newp`; `head->next = NULL`.
for 循环推进 pre, if 判断 `pre->next->num >= newp->num` 后跳出,
pre 正好停在插入点的前驱

## 7.4 链表算法

去重, 反转, 插入排序都是"拆链重建": 先用临时变量保住后继,
再改指针, 最后把新链挂回去

(1) 删除相邻重复时 prev 不动, 因为删完后新后继仍可能与 prev 相同
(2) 反转四步固定顺序: 存后继, 改指向, prev 前进, current 前进
(3) 反转返回的是 prev, head 已变成尾结点
(4) 插入排序每轮从原链摘下结点, 有序插入新链
(5) 插到最前面时要更新头指针, 这是最容易漏的一步
(6) 不带辅助表元要 `prev == NULL` 特判首结点, 带辅助表元可省
(7) 想保持稳定, 前插判断用 `<` 而内层查找用 `<=`

```c
while (current) {
    SListNode *next = current->next;   /* 保存后继 */
    current->next = prev;              /* 反转指向 */
    prev = current;
    current = next;
}
return prev;                           /* 新头指针 */
```

[注意] 递归或循环里改 `p->next` 之前必须先存下 `p->next`,
否则剩下的结点再也找不回来

例7-12: 删除 `3->3->4->4->2->1->5->5->6` 中相邻重复的结点, 写出结果

解: `3 -> 4 -> 2 -> 1 -> 5 -> 6`. 只比相邻一对,
相同值不相邻时删不掉

例7-13: 说明 `function1` 的功能 (`prev = NULL; current = head;`
循环内四步改指针, 返回 prev)

解: 就地反转单链表, 返回新头指针. 若漏掉 `current = next` 会死循环

例7-14: 对 `23 -> 13 -> 15 -> 23 -> 23 -> 16 -> 54 -> 23` 调用
func,
写出返回的链表与功能

解: `13 -> 15 -> 16 -> 23 -> 23 -> 23 -> 23 -> 54`;
功能是对链表做插入排序,
原链表被破坏. `if (p2 == h2)` 时插到最前并更新头指针

例7-15: 删除链表中所有奇数结点, 填 4 空
(判断条件, 删首结点, 删中间结点, 释放)

解: `p->data % 2 != 0`; `head = p->next`; `p = p->next`;
`free(tmp)`.
顺序必须是先 `p = p->next` 再 free

例7-16: 用插入排序对带辅助表元的链表 `list_t` 排序, 不许新建结点

解: 维护 `sorted` 与 `cur` 两条链, 每轮摘下 cur 有序插入 sorted,
最后 `list->head->next = sorted`. `sorted == NULL` 要单独处理

## 7.5 动态内存

malloc 只申请不清零, calloc 申请并清零, 失败都返回 NULL;
堆内存不会自动回收, 必须与 free 一一配对

(1) `malloc` 返回 `void *`, C 里不需要强制转换, 那是 C++ 的要求
(2) `calloc(n, size)` 会把内存清零, `realloc` 调整已分配块大小
(3) 申请结点的写法是 `malloc(sizeof(struct Node))`, 不加 `*`
(4) 惯用法: 分配与判空写在一起,
`if ((p = malloc(...)) == NULL) exit(0);`
(5) `free` 之后不能再访问该指针, 要在 free 之前保住后继
(6) `free` 只能释放 malloc, calloc, realloc 返回的指针
(7) `(*n)++` 的括号不能省, `*n++` 改的是指针

```c
int *a = malloc((*n) * sizeof(int));      /* 个数乘类型大小 */
if (a == NULL) exit(0);                   /* 分配失败就退出 */
...
free(a);                                  /* 与 malloc 配对 */
```

[注意] malloc 的参数是字节数, 要写 `n * sizeof(int)` 而不是 `n`;
`sizeof(struct Node*)` 申请的是指针大小, 会少一半

例7-17: 关于动态内存分配说法错误的是
A. malloc 返回的指针需要强制转换  B. 用 free 释放动态内存
C. 动态分配的内存不会自动初始化  D. calloc 会把内存初始化为零

解: A. `void *` 在 C 里可隐式转换, 强制转换是 C++ 的要求

例7-18: 关于动态内存分配描述错误的是
A. malloc 的内存必须释放  B. calloc 会初始化为 0
C. 分配失败返回 NULL  D. 动态内存可以自动释放

解: D. 堆内存不会自动回收, 这是内存泄漏的根源

例7-19: 读入两组数组并判断两个数中是否恰有一个为负, 填 4.1.1 到 4.1.4

解: `"%d", n`; `(a = malloc((*n) * sizeof(int))) == NULL`;
`i = 0; i < *n; i++`; `(a1[k1] < 0) ^ (a2[k2] < 0)`.
形参本身是指针, 不需要再写 `&`; "有且仅有一个"就是异或

例7-20: 建立整数数组并升序插入, 填 24.1 到 24.5

解: `k = *n - 1`; `d[k] <= para`; `(*n)++`;
`(device = malloc(n * sizeof(int))) == NULL`;
`device, &k, para`.
从后往前扫, 初值取最后一个下标; 计数用指针才能带出函数

## 7.6 字符串与堆内存

返回堆内存的函数由调用方 free; 拷贝时 `strlen` 不含 `'\0'`,
所以申请长度永远是 `len + 1`

(1) 压缩连续空格: 当前位置与下一位都是空格时只跳过, 不写入
(2) `malloc(len + 1)` 的 `+1` 是留给 `'\0'` 的
(3) 函数返回堆内存时, 调用方负责 free
(4) 健壮性检查: `if (!src) return NULL;` 与
`if (!result) return NULL;`
(5) 分割字符串三步: 先数分隔符, 再申请指针数组, 最后逐段切分
(6) 子串个数初值是 1, 因为 n 个分隔符切出 n+1 段
(7) `strncpy` 不补 `'\0'`, 必须手动写 `res[idx][len] = '\0';`

```c
if (src[i] == ' ' && src[i + 1] == ' ')
    i++;                              /* 跳过, 不输出 */
else
    result[j++] = src[i++];          /* 否则拷过去 */

res[idx] = malloc(len + 1);           /* 留一格给 '\0' */
```

[注意] 只压缩连续空格, 不去首尾空白; 连续分隔符会切出空串,
需要时得自行过滤

例7-21: `ostr` 把 `"This    is    a      test string."`
压缩后输出什么,
函数功能是什么

解: `This is a test string.`; 功能是把连续多个空格压成一个.
它不负责去首尾空白, 首尾各留一个空格

例7-22: 写 `char** str_split(const char* src, char c, int *out_length)`
按分隔符切分子串

解: 三段式. 先数分隔符得 `n`, 再 `malloc(n * sizeof(char *))`,
然后以 `start` 记起点逐段切: 遇分隔符或 `'\0'` 时长度为 `i - start`,
拷出并补 `'\0'`, 最后 `*out_length = idx`.
指针写回才有效, 写成 `out_length = idx;` 调用方看不到
